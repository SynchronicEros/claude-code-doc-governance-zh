# upgrade：比對範本更新與擴增治理

範本正本在公開 repo `SynchronicEros/eros-kmu-learning-example`（CC BY 4.0）。本 skill 不內建範本內容，一律在執行當下下載最新版做比對。

```bash
B=https://raw.githubusercontent.com/SynchronicEros/eros-kmu-learning-example/main
```

下載一律用 `curl -fsSL "$B/<網址後段>"` 讀到暫存處（不要直接寫到使用者的檔案上），網址後段：`CLAUDE.md`、`README.md`、`%E6%B2%BB%E7%90%86%E6%93%B4%E5%A2%9E%E6%8C%87%E5%8D%97.md`（治理擴增指南）。**不要用網頁讀取工具，也不要憑記憶補寫內容。**

## 前提

目前資料夾須有 `CLAUDE.md` 與 `決策紀錄.md`。沒有的話，請使用者先用 `setup` skill 建立，或確認是不是開錯資料夾。

## 先問使用者要做哪一種

- **甲：比對範本更新**——範本日後增補的內容，不會自動進到已建立的資料夾。
- **乙：擴增治理**——遇到具體問題（例如同一個錯誤犯了第二次），想加規範。

## 甲：比對範本更新

1. 下載範本最新的 `CLAUDE.md`、`README.md`（看其中的「更新紀錄」節）與治理擴增指南。
2. 和使用者的 `CLAUDE.md`、`治理擴增指南.md` 逐節比對，只列出**範本有、使用者沒有**的條文或段落。
3. 使用者自己改過或新增的內容一律視為使用者的決定，**不列為差異、不提議改回範本**。`CLAUDE.md`「目錄結構」表中，對應的用途目錄在使用者資料夾不存在者（`init` 依使用者選擇刪除），也不列為差異。
4. 以表格列出每一項：範本條文、建議放在使用者檔案的哪一節、利、弊；由使用者逐項決定要不要加入。
5. 只加入使用者同意的項目，用插入的方式，不整檔覆蓋。
6. 每加入一批，在 `決策紀錄.md` 最上面加一筆（編號接續現有最大的 D 編號），記下加了什麼、來源是範本哪一節。

## 乙：擴增治理

1. 請使用者用一兩句話描述遇到的問題。
2. 下載治理擴增指南，找出對應的階段或小規則；指南的原則是「痛了才升級」，沒有具體問題就不加。
3. 依指南寫法，替使用者擬出具體條文（例如禁止事項 N1 的錯誤寫法、正確寫法、適用範圍、例外），附在 `CLAUDE.md` 的哪一節，並列出選項與利弊。
4. 使用者同意後才寫入，並在 `決策紀錄.md` 加一筆。

## 不做的事

- 不整檔覆蓋 `CLAUDE.md` 或任何使用者檔案。
- 不修改 `LICENSE` 與 `README.md` 的〈授權與致謝〉一節。
- 不刪除任何檔案；不自行 commit 或 push。
